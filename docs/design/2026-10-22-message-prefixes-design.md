# 会话消息前缀统一 设计

> issue: gofer-as5h｜ 状态：0.2 已批准（2026-10-22，按推荐）｜ 2026-10-22

## 背景

gofer 送进 agent 会话的文字有十来种，前缀是各功能各自加的，没有统一规则：

| 来源 | 现在的前缀 | 问题 |
|---|---|---|
| 用户 web 新消息 | `[来自 web，<用户>]` | — |
| 用户回复会话的提问 | `[gofer web 回复]` | 以 gofer 开头，像系统消息，其实是用户本人 |
| job 结束通知（传话 / 注入） | `[gofer 通知] [gofer job 完成] …` | 两层方括号 |
| job 结束（Stop 等待里） | `[gofer job 完成] …` | 同一件事两种写法 |
| 唤醒 | `[gofer wakeup]` | 中英混用 |
| 工作项请求 | `[gofer 工作项交接请求 <id>]`、`[gofer 工作项汇报请求 <id>]` | 编号夹在前缀里 |
| 管家带话 | `[gofer 管家带话]` | — |
| 记忆注入 | `[gofer 记忆 · 因“…”命中]`、`[gofer 记忆 · 执行 “…” 前]` | — |
| 杂项 | `[gofer] …`（话题提醒、传话人启动） | 没有类型 |
| 信件 | `<gofer-mail …>`、`<gofer-mail-wake/>` | XML 标签 |

2026-10-22 实际出过错：注入路径给系统通知也加了 `[gofer web 回复]`，agent 把 job 结束通知当成了用户本人的回复（已修，d35cc685）。

## 目标

1. 一眼分清两类：**用户本人说的**与 **gofer 系统发的**。
2. 每种消息一个固定前缀，格式统一，写在一个地方（常量表），生成与识别都只用这张表。
3. agent 能稳定地把系统消息与用户输入区分开；gofer 自己的 hook 也只按这张表判断。

## 设计

### D1 前缀表

格式：方括号内是「来源 · 类型」，后面一个空格接正文。

| 类型 | 新前缀 | 来源 |
|---|---|---|
| 用户 web 新消息 | `[来自 web，<用户>]` | 用户（不变） |
| 用户回复会话的提问 | `[来自 web 回复，<用户>]` | 用户 |
| job 结束 | `[gofer · job 完成]` | 系统 |
| 唤醒 | `[gofer · 唤醒]` | 系统 |
| 工作项交接请求 | `[gofer · 工作项交接]`（编号放进正文） | 系统 |
| 工作项汇报请求 | `[gofer · 工作项汇报]` | 系统 |
| 管家带话 | `[gofer · 管家带话]` | 系统（转达，正文里写明转达谁的话） |
| 记忆注入 | `[gofer · 记忆]`（命中原因放进正文） | 系统 |
| 话题提醒等杂项 | `[gofer · 提示]` | 系统 |
| 信件 | `<gofer-mail …>`、`<gofer-mail-wake/>` | 不变（信件可能来自其他会话，用标签携带发件方属性） |

规则：

- **用户本人**的消息一律以 `[来自 web` 开头，且带用户名。
- **gofer 系统**的消息一律以 `[gofer · ` 开头，不再出现 `[gofer 通知] [gofer job 完成]` 这种叠加。
- 正文里需要的编号、原因放在前缀之后，前缀本身固定。

### D2 一处定义

- 新建 `internal/msgprefix`（或放进现有的最底层公共包）：每种类型一个常量，加 `Format(kind, body)`、`Classify(text) (kind, fromPerson bool)`。
- 所有生成方（sessionrelay、hookrelay、job wakeup、work 请求、管家、记忆注入、messenger）改用它；`IsHarnessPrompt`、`webMessageBody`、`webReplyContinuation`、`injectText` 改用 `Classify`。
- 测试：表里每一项生成后能被 `Classify` 正确识别；用户类与系统类互不混淆。

### D3 兼容（G032）

- 识别侧在 3 个版本内同时认旧前缀（会话里还有旧消息、旧版 worker 可能还在发），打 `DEPRECATED(v0.185): remove in v0.188`。
- 生成侧直接切到新前缀。

### D4 对外说明

- `gofer repo prime` 注入的说明、skill references、prompt 注入段里关于「[来自 web] 是用户本人」的说法，改为说明这张表：`[来自 web…]` 是用户本人，`[gofer · …]` 是系统消息、不是用户输入。
- suga 若有按旧前缀识别的逻辑，发消息请 suga 会话同步（先查 suga 是否依赖）。
- 本工作区的记忆（「[来自 web] 消息就是用户本人」等）随之更新。

## 已定（2026-10-22 用户批准，按推荐）

1. 系统消息格式 `[gofer · <类型>]`。
2. 用户回复改为 `[来自 web 回复，<用户>]`。
