## 背景与目标

用户 2026-10-20 反馈：整理器 / 管家的建议质量不行，老把测试会话拿出来整理和建议。用户随后确认：

- 第一条（测试 / 短会话不进整理与管家）要做；
- 提示词希望能配置，倾向于「基础核心的放配置文件，扩展性设置存数据库的配置表」，配置方便、生效快，CLI 也能改，并提供通用的 `gofer tool api` 命令；
- 整理器已在设置里配成 suga + deepseek-v4.1-flash，质量问题主要在提示词与材料，不是模型。

## 已确认事实（代码核对，2026-10-20）

- **草稿从哪来**：会话出现第一条人工提问就建草稿工作项（`internal/sessionrelay/service.go` 注册与心跳 → `work.Service.OnHumanPrompt` → `jobstore.EnsureDraftWorkItemForSession`）。唯一条件是该会话还没挂在工作项上；不看项目、轮数、时长、标题。
- **现有排除**：只有 hook 层——设了 `GOFER_JOB_ID`（gofer 起的 job）或 `GOFER_MESSENGER=1`（传话人）跳过；cwd 前缀在 hook 进程环境变量 `GOFER_HOOK_IGNORE_CWDS` 里的跳过（只能在启动会话的环境里设，不在 config.yaml）。
- **整理器选谁**：`scanSummarize` 遍历全部未结工作项（含草稿），会话 offline / ended **立即**算可以整理；占每日额度（默认 50）。
- **管家选谁**：`reviewItems`、`BuildPrime`、`scanEvents` 都包含草稿；测试会话结束会以事件形式再次进入巡检。
- **提示词**：全部写死在代码里——管家 `internal/steward/prime.go` `rolePrompt`、`review.go` `reviewPrompt`；整理器 `internal/work/summarize.go` `buildPrompt`（要求输出固定 JSON）。没有任何覆盖入口。
- **已有 KV**：`work_kv(k, v)` 是工作项子系统的小状态表（管家笔记等），没有类型、版本、作者与审计，不适合当通用设置表。

## 总体方案

1. **降噪（规则，默认开）**
   - 建草稿门槛：同一会话第 **2** 次人工提问才建草稿（第一次多半是试一下）；目录不属于任何项目的会话不建；命中排除规则（项目、目录、标题模式）的会话不建。
   - 整理器与管家只看「有分量」的会话：已结束且存活不足 **10 分钟**、人工提问少于 **3** 次的会话跳过（不占整理额度、不进管家巡检与事件）。
   - 已经建出来的草稿不动；规则只影响之后。
2. **扩展设置（数据库）**：新表 `settings`，存「可在运行中调整、不影响启动」的设置；每个键在代码里登记（名称、类型、默认值、说明、校验、谁能改），读时取「数据库值，没有就用默认值」，改了立即生效。第一批键：三段提示词与降噪规则的阈值、排除名单。
3. **入口**：web「设置 → 扩展设置」页（列出全部键，显示当前值 / 默认值 / 是否改过，可编辑、恢复默认，提示词用多行编辑器）；CLI `gofer settings ls|get|set|reset`；HTTP `GET/PUT/DELETE /v1/settings/{key}`；MCP 不提供写。
4. **`gofer tool api`**：通用 HTTP 调用，`gofer tool api [-X METHOD] <path> [-f key=value]... [--input file|-]`，自动带 server 地址与 token，输出 JSON（`--jq` 可选过滤），参照 `gh api` 的用法。

## 范围与非目标

- 范围：上面四项；整理器默认提示词按「只整理有进展的会话、不评价测试性质的操作」改写一版（作为新默认值）。
- 非目标：把 config.yaml 里已有的配置项搬进数据库（核心配置仍在文件里）；信箱界面与广播；管家 / 整理器的模型选择（已可在配置里改）。

## 扩展设置的规则

- **分层清楚，不重叠**：一个设置要么在配置文件里，要么在扩展设置里，不会两处都有、互相覆盖。判断标准：影响启动、安全边界、连接、权限的放配置文件；只影响 agent 的措辞、阈值、名单这类「调了立即见效、改错了也能马上改回」的放扩展设置。
- **键名**：`<子系统>.<名称>`，例如 `prompt.steward.role`、`prompt.steward.review`、`prompt.work.summarizer`、`work.draft.min_prompts`、`work.draft.exclude_projects`、`work.draft.exclude_cwds`、`work.draft.exclude_title_patterns`、`work.short_session.max_minutes`、`work.short_session.max_prompts`。
- **类型与校验**：string（可设最大长度）、int（范围）、bool、string 列表、正则列表（保存时编译校验）。非法值拒绝保存并给出原因。
- **提示词的覆盖方式**：每段提示词有两个键——`…`（整段替换）与 `….extra`（追加在默认提示词之后）。推荐用 `extra` 写偏好，跟得上以后的默认版本更新；整段替换给需要完全控制的人。整理器要求的 JSON 输出格式说明**总是**由代码追加在最后，替换不掉，保证解析不坏。
- **生效**：进程内缓存加版本号；本进程写入立即生效，多进程部署 5 秒内生效（与授权缓存同一做法）。
- **权限**：读需要 `settings.read`（种给 users）；写需要 `settings.write`（中风险，不种，只给根管理员与显式授权）；受限调用方（ceiling）只能读不能写。每次写入记审计（谁、哪个键、旧值摘要、新值摘要）。
- **导出与迁移**：`gofer settings export` 输出 YAML，`gofer settings import <file>` 导入（逐键校验，先预览差异，`--yes` 才写）；备份 / 换机时用。
- **恢复默认**：`reset` 删除该键的数据库值，回到代码里的默认。默认值随版本更新时，没改过的键自动跟上。

## 关键流程

- 会话第 1 次人工提问：不建草稿（记录提问次数）。第 2 次：检查排除规则，不命中就建草稿。
- 整理器扫描：会话已结束且「存活 < max_minutes 且 提问 < max_prompts」→ 跳过并记一条跳过原因（整理日志可见），不占额度。
- 管家巡检与事件：同一判据过滤；`BuildPrime` 的未结工作项也按此过滤。
- 改提示词：web 或 `gofer settings set prompt.work.summarizer.extra "…"` → 下一次整理即用新提示词；job 详情里能看到实际发出的提示词（现状已有）。

## 安全、数据、运维与回滚

- 新表 additive 迁移；回滚旧版本时表被忽略，行为回到写死的提示词。
- 提示词可能被写入不当内容：写权限只给管理员；审计留痕；web 编辑页显示与默认值的差异。
- `gofer tool api` 只用调用者自己的 token，权限由服务端判定，与其他命令无差别；不在日志里打印请求体中的秘密（沿用现有脱敏）。

## 测试计划

- 草稿门槛与排除：第 1 / 2 次提问、无项目、排除名单、正则；已存在草稿不受影响。
- 短命会话：整理器与管家跳过、额度不变、跳过原因可见。
- 设置：类型校验、默认值回落、缓存失效（本进程即时、跨进程 5 秒）、权限（读 / 写 / 受限调用方）、审计、导入导出。
- 提示词：extra 追加、整段替换、JSON 格式说明总在末尾。
- `gofer tool api`：GET / POST / 带文件、错误码透传、`--jq`。

## 决策

以下为本稿的提案，待用户确认：

1. **扩展设置放数据库（推荐）**，按上面的分层规则只放「措辞、阈值、名单」类设置；配置文件保持核心配置。备选：提示词用文件（`*_prompt_file`）——改起来要登录主机编辑文件、门槛高，不推荐。
2. **建草稿门槛默认第 2 次人工提问**，无项目的会话不建。备选：门槛 1（现状）只靠排除名单。
3. **短命会话默认判据：存活 < 10 分钟且提问 < 3 次**，两个阈值都可在扩展设置里改。
4. **提示词覆盖用 extra（追加）+ 整段替换两个键**，JSON 格式说明不可替换。
5. **CLI 命令名**：`gofer settings ...` 作为顶级资源命令（它是核心资源，与 `config` 并列；G033 的小工具规则不适用），`gofer tool api` 放在 tool 组下。备选：`gofer config ext ...`。
6. **权限**：新增 `settings.read`（种给 users）与 `settings.write`（不种）。
7. **默认提示词改写一版**：整理器强调「只记录有实质进展的会话，不对试用 / 测试性质的操作给建议」，管家巡检同样加这一条。
