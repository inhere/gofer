# 信箱广播（群发）设计

> issue: gofer-metc ｜ 状态：草案 0.1（待批）｜ 2026-10-22
> 基于：`docs/design/2026-10-16-session-topics-mailbox-and-inbox-design.md`（信箱第一、二期）

## 背景

信箱现在一封信只有一个收件方。地址如果匹配到多个会话（例如 `topic:login` 命中两个会话），按现有规则**不猜**：信件转为「待指派」进收集箱，由人挑选。

用户希望能一次通知多个会话，例如「告诉 gofer 项目的所有会话：v0.183.1 已发布，合并前不必再先提交 tracker」。

## 目标

1. 一封信可以发给多个会话：显式列出收件人，或用一个选择器匹配到的全部会话。
2. 每个收件人的送达、已读、回复状态单独可见，发件人看得到「送达 n/m、已回复 k/m」。
3. 收件人的回复回到发件人，挂在同一个对话串里。
4. 权限与单封信件一致，并且对广播额外限流，防止刷屏。

## 不做（第一版）

- 「回复全部」：收件人的回复只回给发件人，不会转给其他收件人。
- 动态订阅：发送时解析出收件人名单，之后新出现的会话收不到。
- 急件广播：广播一律按普通件投递，不触发急件的立即唤醒。
- job / steward 凭据发广播：第一版只允许用户类调用方发。

## 设计

### D1 地址：显式开启的「发给全部」

现有地址的含义不变：匹配到多个时仍然转「待指派」。广播必须由发件人显式开启，有两种写法：

- **多个收件人**：`--to` 可以重复，每个都必须解析到唯一收件方，例如 `--to session:a --to topic:login`。
- **选择器前缀 `each:`**：`each:<地址>` 表示「这个地址匹配到的全部可投递会话」。
  - `each:topic:<关键词>`、`each:path:<子路径>`：沿用现有的主题和路径匹配规则，但取全部命中，而不是只取唯一命中。
  - `each:project:<key>`（新增）：该项目下全部可投递的会话。
  - `each:agent:<名字>`：该类 agent（claude / codex / suga）的全部可投递会话。

「可投递」沿用现有规则：会话存在、未结束、调用方有权限投递。不在线的会话照常保留到送达期限。

### D2 存储：一个收件人一行

- 发送时解析出名单（最多 `mail.broadcast_max_recipients`，默认 20 个），**每个收件人一行 mail**，共用同一个 `thread_id`，各行独立走现有的状态机和投递路径。投递器、hook 注入都不用改。
- mail 表新增 `broadcast_id` 列（additive 迁移）：取第一行的 id；单封信为空。
- 收件人看到的信件标签里多两个属性：`<gofer-mail id=".." broadcast="b12" recipients="5" …>`，让 agent 知道这是群发，不必以为只发给了自己。

### D3 回复与状态

- 回复照旧：用 `gofer session mail reply <id>` 回到发件人，挂在同一个对话串。
- 发件人查看：`gofer session mail read <id>` 对广播会列出收件人表（收件方、状态、送达时间、是否已回复）；web 信箱的对话视图里，广播显示为一张卡片加收件人状态条，回复按收件人分组。
- 收件人过期：单封信过期会转「待指派」进收集箱。广播如果也这样，可能一次产生十几条待指派，所以广播的过期副本只标为 `expired`，**不进**收集箱，在发件人的收件人表里能看到。

### D4 权限与限流

- 对每个收件人按单封信的规则检查权限（他人的终端会话需要 `session.reply.others`，他人的会话 job 需要 `job.manage.others`）：
  - 显式列出的收件人里，只要有一个没有权限，整封拒绝并说明是哪个（防止发件人以为发出去了）；
  - `each:` 选择器按权限**过滤**，只发给有权投递的会话，并在返回结果里写明「匹配 N 个，投递 M 个，因权限略过 K 个」。
- 限流：
  - 每个调用方每 10 分钟最多 5 次广播（`mail.broadcast_rate`），超出返回 429；
  - 收件人超过上限直接拒绝，并提示收窄选择器；
  - 解析出 0 个收件人时返回 400，不建任何信件。
- 路由按 G056 登记。`POST /v1/mail` 沿用原路由，请求体 `to` 改为字符串或字符串数组；广播的判定和限流在 handler 内。

### D5 接口

- HTTP：`POST /v1/mail` 的 `to` 接受数组；响应新增 `broadcast_id` 和 `recipients[]`（地址、解析结果、mail id、因权限略过的原因）。`GET /v1/mail/{id}` 对广播信件返回 `broadcast` 段（收件人状态汇总）。
- CLI：`gofer session mail send --to <地址> [--to …] "正文"`；`each:` 写在地址里。
- MCP：信箱发信工具的 `to` 接受数组。
- web：写信框的收件人改为可多选（会话下拉，外加「按项目 / 主题 / agent 全部」），发送前预览「将投递 M 个会话」。

### D6 默认值

| 配置 | 默认 | 说明 |
|---|---|---|
| `mail.broadcast_max_recipients` | 20 | 单次广播最多收件人数 |
| `mail.broadcast_rate` | `5/10m` | 每个调用方的广播频率上限 |

## 待定（请批）

1. **选择器写法**：推荐 `each:` 前缀，好处是现有地址的含义（多个命中就转待指派）完全不变。另一种写法是 `--all` 开关加原地址，更短，但同一个地址加不加开关语义不同，容易误用。
2. **显式收件人里有一个没有权限时**：推荐整封拒绝。另一种做法是跳过它、照发其余的。
3. **广播的过期副本不进收集箱**：推荐不进，只在收件人表里标 `expired`。
