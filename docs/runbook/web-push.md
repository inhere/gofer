# Web Push 通知（WEB-11 W2b）

工作台可以把"等你处理"的事项推送到浏览器/手机系统通知：待答审批或提问（blocked）、待评审（`needs_review`，以及按 F16 口径算 review 的终态）、`plan.blocked`。审批类（permission）通知带「允许」「拒绝」按钮，不用打开页面就能作答。

## 前提

- **页面必须是安全上下文**：`https://…` 或 `http://localhost` / `127.0.0.1`。纯 http 的内网地址（如 `http://192.168.x.x:8767`）浏览器不给 Push，设置页会显示原因；这时工作台退化为标题计数 `(N) gofer` + 顶部提示条，已有的 IM 通知不受影响。远程用推送，给 gofer 前面挂一层 HTTPS（反向代理或隧道）。
- 浏览器需支持 Service Worker 与 PushManager（Chrome/Edge/Firefox；iOS Safari 需先"添加到主屏幕"作为 PWA 打开）。

## 开启

1. 打开 web → 设置 → 通知 → 「开启本设备推送」，浏览器询问通知权限时允许。
2. 同页「发送测试推送」，应收到一条测试通知（只推给自己）。
3. 列表里能看到本 caller 名下所有已开启的设备；「关闭」删除当前设备的订阅。

## 服务端

- VAPID 密钥对在第一次需要时自动生成：`<config-dir>/push/vapid.json`（0600）。删除后重启会生成新密钥，**所有已有订阅随之失效**，各设备需重新开启。
- 可选配置（改后需重启 server）：

  ```yaml
  server:
    push:
      vapid_subject: mailto:you@example.com   # 默认 mailto:gofer@localhost
  ```

- 推送服务返回 404/410 的订阅会被自动删除；其他失败只记日志，不影响 job 事件。
- 同一会话 30 秒内的多条事件合并为一条通知（后一条覆盖前一条）。
- 通知只含标题、≤120 字摘要和跳转链接，不含日志正文。

## 通知里的「允许/拒绝」

- 按钮携带一次性动作令牌（HMAC 签名，绑定 caller / job / interaction / 可选项，10 分钟有效，用一次即失效；server 重启后未用的令牌全部失效）。
- 令牌过期、已用、审批已在别处答过，或该 caller 已从配置删除时，点按钮会改为打开工作台对应会话。
- 作答记录的来源为 `push`。

## 排障

| 现象 | 处理 |
|---|---|
| 设置页显示"需要 HTTPS 或 localhost" | 见前提；换 HTTPS 访问地址 |
| 开启了但收不到 | 先点「发送测试推送」；系统/浏览器的通知权限是否被关；手机省电策略是否拦了浏览器 |
| 点「允许」后没反应、打开了页面 | 令牌已失效（见上），在页面里作答即可 |
