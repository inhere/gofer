## 导航

- 顶栏一行是常看的 6 项：今天 · 工作台 · 工作项 · 计划 · 任务 · 会话；其余在「更多 ▾」下拉里，横排展示：一个分组一行，行首是分组标题，后面接着横排链接——「工作」：Issues · 统计；「配置」：Agents · Runners · 项目 · 工作流 · 定时。面板宽度随内容，一行放不下时自动换行，不会超出视口。当前页面在下拉里时「更多」高亮；键盘可用（Enter / Space 打开，Esc 关闭）。
- 左上角 Logo 回首页「今天」（`/today`）；连接状态圆点在 Logo 右侧；工作项菜单有「等我」数量徽标。
- 顶栏右侧：「新建任务」、「随手记」、信箱（信封按钮进 `/mail`，宽屏带「信箱」文字、窄屏只留图标，有待指派信件时带数字徽标）、worker 申请与「待我决策」提醒、设置菜单；「设置」在主导航末尾（`/settings`）。定时页标题栏「+ 新建」。
- 窄屏（≤900px）顶栏只留右侧按钮，屏幕边缘的小标签打开抽屉：半圆标签贴在左 / 右边缘（默认左侧、约视口高度 45% 处），按住可以上下拖动、拖到另一侧，松手吸附到最近一侧（垂直位置限制在顶栏下方到视口底部上方 200px 之间，拖到边界会停住，不进底部输入区）；在输入框里打字、页面滚动或抽屉展开时它会淡出让开（点遮罩或菜单项关抽屉）。位置记在浏览器里。抽屉里是完整的分组列表（含信箱），不做下拉。
- 标题 / 开关旁标有「实验性」的功能（工作流与模板、信箱、plan 的 leader 回合、决策 hook 等）仍在调整：行为与配置可能变化，用之前看一眼[稳定性说明](https://github.com/inhere/gofer/blob/main/docs/guide/stability.md)。标注只是提示，不影响任何操作。

## 今天与「待我决策」

- **早报一行**：自上次打开以来完成 / 失败 / 新提交数，点开是当天工作摘要（开了管家时附点评）。
- **待我决策**：所有等人的事汇成卡片——工具调用审批、`gofer_ask_human` 提问、会话等回复、待验收 job、待批准 job、工作项等我 / 需现场 / 到期、整理与合并建议、阻塞的 plan、记忆整理建议、终端授权请求、worker 自助注册申请（只有持 `worker.manage` 的人会看到）、信箱的待指派信件（没人接收的信，点它跳信箱的待指派页签）。按「会超时 / 卡住别人 / 可稍后」分组，前 5 张在首页，其余点「还有 N 张」。
- **卡片**：来源 · 项目 · 等了多久 · 多久后超时 · 「卡住 N」/ 标题（点了跳到负责的页面）/ 一句话 / 操作（批准、回复、通过、附意见重跑、采纳等）；「详情」里有阻塞明细、改动数据和管家建议。管家写过建议的卡，主按钮变成「按建议：X」。
- **撤销窗口**：点操作后卡片收起，底部提示「撤销 5s」，倒计时结束才真正执行；按 `z` 撤销。快超时的卡立即发送。
- **稍后**：卡片「稍后」→ 1 小时 / 明早 9:00 / 等相关 job 结束；稍后**不暂停超时**，到点仍按原规则兜底。到点、相关 job 结束或有新动静时卡片提前回来并带标记。队列底部「已稍后 N」可放回。
- **专注处理**：全屏一次一张；键位 `j` / `k` 上下张、`1`–`9` 按顺序触发操作、`a` 通过 / 采纳、`r` 回复、`i` 详情、`h` 稍后、`s` 跳过、`z` 撤销、`Esc` 退出；手机左右滑。
- **全局浮层**：任何页面点顶栏「待我决策 N」（会超时变红）或按 `g` 再 `d` 打开，处理完不离开当前页。
- **顶栏提示条**：新出现的待批准 job（`--hold`）、人工介入请求、决策请求会在顶栏弹一条提示（同一条只弹一次，处理掉就不再提示）；点它就跳到其中一处——待批 job 的批准面板在 job 详情页页首。
- **并行中泳道**：未结的工作项与在跑的 plan 一行一件事，显示在跑的 agent、进度点、健康度、耗时与用量；点行打开工作项抽屉或 plan 详情。
- 底部状态条：runner 在线数与离线名单、今日 job 用量、管家今日动作、版本；异常项变红。

## 验收台与待批准

- **验收面板**（job 详情页首，`needs_review` 时）：先列「验收标准」（勾选框只是本页对照），页签有汇报、发现（「## 发现但不碰」各条，可复制为 issue 命令）、经验（填 key 和 kind 后接受，或拒绝）、提交、Diff（按文件折叠，声明了 scope 时标出「范围外」文件）、验证、用量；底部 Accept / Reject（拒绝必写理由，可勾「自动续投」）。
- `/review`（页面标题「待验收」）列全部待验收 job（等最久的在前），行内「通过 / 拒绝」。待验收 job 同时进「待我决策」（exec job 默认不进，勾「含 exec 待验收」才显示）。CLI 等价：`gofer job review <id>`。
- **待批准**（`--hold` 的 job）：job 详情页首「⏸ 等你批准」面板显示理由、完整命令、项目 / cwd / runner、过期倒计时，「批准」一键执行、「拒绝」可写理由。job 一进待批准，顶栏就弹一条提示（带标题与命令），点它直接到该 job 的这个面板；批准 / 拒绝 / 过期后提示与卡都消失。见 [hold-approval.md](hold-approval.md)。

## 任务 / 计划 / 工作流

- **任务**（看板；顶栏导航项叫「任务」，页面标题是「任务看板」）：按状态过滤（含「⏸ 待批准」）；详情页有**「消息」区**（只对 ACP 持续会话 job 显示并请求，exec / 一次性 cli-agent job 不显示，gofer-h7hy；发给 agent 的消息：首条 prompt 剥掉注入的 rules 段、可展开全文，接着是持续会话各轮 `session say` 与 agent 回复摘录）、日志（运行中只拉末尾、断线续传、「加载更早」）、stderr 事件流的结构化视图、提交、verify、用量、唤醒块（列表 / 开关 / 新建 / 触发历史）、评论、worktree 区（「合并到基线」，远程 runner 灰显）、「重跑」（可改模型 / 预算等）、「继续会话」（续接方式单选）、「从此会话新开」、有权限时「删除」。「取消」按服务端 `job cancel` 的允许范围显示：排队中（`queued` / `waiting_dir` / `recovering` …）、执行中、待批（撤回）等非终态都有，终态与 `needs_review`（要 accept / reject）没有。**「继续会话」表单可以改锁定目录**（gofer-jkd2）：续接默认照抄源 job 的锁，会话锁着整个项目根时改用 `gookit/ini` 这类子目录就不再拦着别的 job；会话的 cwd 不变（ACP 续载会话要在同一目录）。
- **新建 job / 会话**：选项目、agent、runner（按项目允许的 runner 过滤，不可用项灰显并写原因）、模型、高级选项里的预算；选了 ACP agent 会默认切到「ACP 持续会话」。旁边还有**运行目录外的三个执行选项**（gofer-jkd2）：**锁定目录**（可多个，项目根相对，留空 = 锁整个 CWD；只动某个子目录就写它，别的子目录的 job 才不用排队）、**等锁时长**（超过即失败，0 = 不限）、**worktree**（独立 checkout，提交落在分支）。三个字段与 CLI 的 `job run --lock` / `--lock-wait` / `--worktree` 一一对应；表单还会列出**项目里的子仓库**（E32 子仓发现），点一下把它们填进锁定目录。
- **计划**：计划看板（拖到 `ready` 即派发，拖到 `done` / `skipped` 即人工标记）；plan 详情有 todo 进度、用量（jobs 与主 Agent 会话分开，下面另列缓存 token 的读 / 写）、「主 agent 会话」面板与「发给主 agent」、决策作答。
  - **接着上一项的会话做**：待办表单里的开关，开了再选一个前序项（新增时默认选本计划的最后一项），派发这个待办时就在**前序项的会话里继续**——不用重新读代码、重新熟悉上下文；任务说明换成这一项自己的。条件不满足时（前序还没完成、换了 agent / 目录 / runner、前序要自动交付、会话链太长……）自动开新会话，并在条目上写「未接续：<原因>」。看板卡片与列表行显示「接续自 <前序标题>」，前置项的卡片上显示「已被 <后继标题> 接续」（同一前序项只接一个后继项）。关掉开关即恢复普通派发。
- **工作流**：扇出步显示为对比视图（每路一列，可并排展开 diff，`join: pick` 时「选这个并合并」，冲突时列出冲突文件、仓库已复原）；新建页有「从模板新建」向导（选项目 → 模板 → 按 vars 生成表单 → 预览步骤 → 提交）。

## 会话与工作台

- **会话**：终端会话列表（等回复置顶），RELAY 开关 auto / on / off 可直接切；会话抽屉里回复、送入终端、起新进程接管、唤醒、解除接管、催办、从此会话新开，显示会话名、当前目录、用量、所属工作项。离线会话灰色徽标。同一句转达答复只显一个气泡（带送达状态的那条）；发送成功后不在输入框上方再提示一遍，失败时才出现错误行。见 [sessions-relay.md](sessions-relay.md)。**新建会话**表单（会话类型 / 项目 / agent / runner / 模型 / **工作目录** / **锁定目录** / 标题 / 第一句话）与新建 job 同口径：会话落在项目根会锁住整个项目根，动子目录就给个锁定目录；填了的值也会随「完整配置」带到 /new 页。
- **会话主题与查找**：卡片和抽屉显示会话的主题与范围（项目根相对子路径）；推断出来的主题灰显并标「推断」，自述 / 人工有来源小标签。「编辑」就地改主题和范围：自己的会话直接改，别人的需要 `session.manage.others`，已结束的会话不能改（按钮灰显并写明原因），范围每行一个相对路径（不能是绝对路径或含 `..`，最多 20 项）。会话页的查找框：输入含 `/` 或 `\` 且无空格按路径，其余按关键词；结果按相关度排序，每张卡片列出命中原因（范围命中 / 主题命中 / 会话名 / 项目），离线会话标「可能不在线」，已结束的会话不参与查找；清除后回到普通列表。
- **工作台**：按线程看会话与 ACP 会话的对话（只呈现用户消息与 agent 回复，工具 / 思考从「查看过程」进 job 详情），新会话表单可选 runner、**工作目录与锁定目录**（gofer-jkd2：持续会话整个会话期间持有锁，尽量锁子目录）；「停止」= 取消当前 job，可取消的条件同 job 详情页的「取消」。手机（宽 ≤900px）下工作台把纵向空间留给消息：主题 / 范围 / 中继状态说明收成一行「主题 · 范围 ▸」摘要，点它才展开（唤醒 / 接管 / 从此会话新开 这组操作不受影响，一直可见）；输入框下方的说明收成一个「?」开关（输入框照旧可用）。桌面布局不变。
- **附图**：工作台会话的输入框与会话抽屉的回复框都能带图片（会话抽屉的 📎 只看 thread 的附件能力位：agent 没在等回复也能发；不可用时原因只写在 📎 的悬停提示里）。三种加法——粘贴（桌面 Ctrl+V / 手机长按粘贴）、把图片拖进输入区、点 📎 选文件（`accept="image/*"`，手机上系统会给出「拍照 / 相册」）。选中即上传：缩略图上显示进度，失败可点「重试」，点 × 删除（还没发出去的会一起从服务端删掉）；上传没完成或还有失败项时「发送」按不下去，免得发出缺图的消息。一条消息最多 6 张、单张上限由服务端定（默认 10MB），超了就地提示、不上传；只收 PNG / JPEG / GIF / WebP（SVG 不收，避免脚本）。手机上大图会自动压到长边 2048 的 JPEG（长边不超 2048 且小于 1MB 的 PNG 截图保持原样），桌面默认发原图、超过 10MB 才压，GIF 不压（压了就丢动画）。发出的消息在历史气泡下有缩略图网格，点开看原图（服务端追加在正文末尾的 `[附图 n] 路径` 不显示，图就在气泡下面；没有附件记录的老消息保持原文）；原图在服务端按保存期保留（默认 14 天），过期后显示「图片已过期」。收件方收不到图片时 📎 置灰并写出原因，不会等发出去才失败。哪些收件方能收：持续 ACP 会话且 agent 声明支持图片（`promptCapabilities.image`）→ 图片直接随消息发出（内联）；其余——命令行会话、终端会话（Claude Code / Codex）、不支持图片的 ACP——会先把图片放到执行机项目目录的 `tmp/gofer-attachments/<日期>/`，再在消息末尾写上 `[附图 n] 绝对路径` 让 agent 自己打开（只有配置里 `image_input` 为 path 的 agent 才行：内置 claude / codex 及其 `-acp` 变体是，suga 不是；suga-acp 持续会话在所用模型能看图时声明支持图片，走内联）；放图失败时整条消息不发、给出原因；老 worker（协议低于 v25）报不出绝对路径，消息里写项目相对路径并注明相对于哪个项目；pty job 不支持附图。截图可能带敏感信息（终端里的 token、地址之类），发之前自己看一眼。

## 信箱

人与会话、job 之间的**信件**往来（发信 / 读信 / 回信与「交给会话」的分派都走信件）：

- `/mail`（顶栏右侧的信封按钮）**按对话显示**：两个会话 / job / 收集箱之间的全部往来是一个对话，不管你发我收还是我发你收，也不管中间开了多少个串。
  - **左栏**一行一个对话：两个人物的名字、最后一封的摘要（纯文本，markdown 标记已去掉）、未读数、急件标记、信件数、最后活动时间；按最近活动倒序。
  - **右栏**是这个对话的时间线（从早到晚）：自己的一方在右、对方在左（两边都不是自己时，先写信的一方在左），回信标「回复 #N」，点它跳到被回复的那封并高亮；正文按 **markdown 渲染**（代码块、标题、列表都正常显示，仍按消毒策略过滤），超长的信默认折叠，点「展开全文」读完；每个气泡角上是投递状态（待送达 / 已送达 / 待指派 …）。
  - **人物卡**：名字是会话主题（没有主题用标题，再没有用 agent · 项目）、副行是 agent · 项目 · 执行机、一个状态点（在线 / 空闲 / 等回复 / 离线 / 已结束），头像首字按 id 稳定取色；悬停看完整 id、cwd 与最后活动时间；会话的名字点一下就打开会话抽屉。job 显示 job 标题，收集箱显示「<你的名字> 的收集箱」。
- **过滤**：全部 / 收件 / 发件 / 待指派。地址栏带 `?session=<会话 id>` 时只看这个会话的往来（会话抽屉里的「信件」一行就是这么跳过来的），`?state=held` 打开待指派页签（Today 的「信件 N 封待指派」卡点「去指派」即到这里）。
- **写信**：地址写 `session:<会话 id>` / `job:<job id>`（在跑的会话 job）/ `topic:<关键词>` / `path:<子路径>` / `caller`（自己的收集箱）；可勾「急件」。正文用 markdown 写，单封上限 32 KB，发得太密会被限速（429）。
- **送达**：普通件在收件会话的下一轮开始注入，急件在轮内下一个工具调用前注入；收件方读信（包括在 web 上打开这个对话）即算送达。打开的对话里收到的未读信会自动标成已读。
- **待指派**：地址没有唯一命中或过了送达期限的信落在这里，页面写明原因；可以「改投」（输入新地址重发，旧的那封撤回）或「撤回」。改投的目标也可从发信 / 改投回答里带回的候选里一点填上。
- **手机宽度**：列表与时间线切换显示（选了对话显示时间线，左上角「← 列表」回来）。
- **会话抽屉**：详情区的「信件」一行显示该会话相关的信件数与「去信箱」链接（没有读信权限时不显示）。

## 工作项、Issues 与 Memories

- **工作项**（`/work`）：顶部「等我 / 到期提醒 / 未整理」计数（点击筛选），按状态分栏或按工作区分组；卡片标出每个字段谁写的、何时；抽屉里改字段、标状态、搁置、提醒、完成 / 放弃、合并 / 拆分、关联、转为 todo、写备注、看日志、整理、请它汇报 / 写交接、采纳建议、删除已结束的项。右下角「问管家」。见 [work-items.md](work-items.md)。
- **收集箱（工作项的「待整理」区）**：待整理区有两个页签——「草稿」（自动生成、还没补目标的条目）和「收集箱」（随手记下、还没整理的条目，每条显示类型标签 想法 / 问题 / 需求 / 记录、来源会话 / job 与记录时间）；`/work?tab=capture` 直接打开收集箱（Today 的「收集箱 N 条待处理」卡点「去整理」即到这里）。收集箱条目不进看板列、分组和计数。顶栏的「随手记」按钮在任何页面都能记一条：写内容、选类型（缺省「记录」）、可选项目，Ctrl+Enter 或「记下」提交，成功后提示条带「去收集箱」链接；手机上是贴底面板。
  - **分派**：点开收集箱条目，抽屉顶部的「分派…」打开对话框。「交给会话」列出按标题和目标匹配出的前 3 个会话（命中原因：主题 / 范围 / 会话名 / 项目；推断出来的命中虚线标「推断」，可能不在线的另标），也可从下拉里选别的会话，确认后给对方发一封信（对方下一轮开始时收到，出处为分派者），条目记下信件 id；信件送达 / 被回复时写进条目的日志，送不出去时显示 server 给的原因、条目留在收集箱；「新建 job」打开新建 job 页（`/new?from_item=<id>`），预填标题 + 目标、项目和（项目相对的）目录，提交后自动把 job 关联到条目，关联失败不影响 job，页面上有「重试关联」；「转 todo」选已有 plan 或新建；「转 issue」选一个已有 id 前缀的仓库（没有前缀的仓库不列出）、可改标题，成功后条目的关联项上该 issue 带「待同步」标记，直到仓库下次 `gofer repo sync` 拉取；「归档」「丢弃」不需要额外信息。没有 `job.submit` 时不显示「新建 job」；他人的会话没有 `session.reply.others` 时不列出。
- **Issues 页「新建 issue」**：页头按钮展开表单，选仓库（只列有 id 前缀的）、标题、描述、优先级、类型，在 server 镜像里新建，仓库下次 `gofer repo sync` 进本地。
- **Issues**：树形 / 平铺、批量操作、「同步」按钮；**Memories** 列表带类型与 doctor 标记。见 [tracker.md](tracker.md)。

## Runners、Agents、项目与设置

- **Runners**：server 本机与每台 worker 一张卡：在线状态、心跳、在跑 job、版本；「工作目录」折叠区显示默认工作空间、roots 映射与各项目在该 runner 上的路径（不存在或被拒的标红）；「传话人」抽屉（状态、最近投递、错误输出尾部、列出可见会话）；「升级」按钮与升级历史（最近 5 次，带时间）；「添加 worker」。
- **待接受**（Runners 页，需要 `worker.manage`）：worker 机器上 `gofer worker join --server <server 地址>` 发起的注册申请列在这里——来源地址、主机名、OS / 架构、gofer 版本与协议版本、提议的 worker id 与标签、它报的 agents 与 roots，以及决定倒计时（默认 2 分钟，到点自动过期）。点「接受…」要输入 **worker 终端上显示的 8 位配对码**（web 不显示码，这正是用来分辨冒名申请的一步），同时可改 worker id（`server` / `local` 是保留名）、选项目、填标签；点「拒绝…」可写理由并勾选屏蔽该来源 10 分钟。server 配置里没开 `server.worker_enrollment.enabled` 时，这一区只显示怎么开启。功能没开或 worker 凭据进来时，这区与顶栏提醒都不出现。
- **Agents**：每个 agent 的健康度徽标（绿 / 橙 / 灰）、「探针」按钮；从内置模板注入的 agent 标「内置」。
- **项目**：项目表单（允许的 agent / runner、交互、exec 等）；内置 `default` 项目标「内置」。
- **Tunnels**：在线转发（可远程「停止」）、server 预设的启动 / 停止、导入本机预设。
- **设置**：编辑配置、「重新读取文件」、「工作项」页（整理器、摘要、管家）等，需管理员。**「设置 → 权限」**管理授权：授权（按对象分组，含孤儿恢复与「有新权限待确认」）、会话授权、权限目录、审计；新增授权可选预设或写模式并实时预览展开结果，高风险要确认，危险级要写出完整权限名并填原因。只有根管理员能改，其余账号与没有根管理员的部署只读。新增授权的展开预览调 `GET /v1/auth/expand`（规则只在服务端一份，输入后稍等才刷新）。缺权限被拒时提示里会写出缺的权限名并指向这里。**按权限显隐**：控制台读一次 `whoami`（登录变化与「重新读取文件」后刷新），没有权限的操作不摆出来——升级 worker（`worker.upgrade`）、添加 / 重载 worker（`worker.manage`）、一键更新（`update.apply`）、写配置（`config.write`）、项目增改删（`project.write`）、删除他人的 job 记录（`job.delete.others`）、托管转发与预设（`tunnel.hosted`）、停他人的转发（`tunnel.manage.others`）；拿不到 `whoami` 时不隐藏，由服务端 403 说话。**Sessions 页的「授权」**：根管理员在会话卡片或详情抽屉点「授权」，只列可授予会话的权限，选 1 / 4 / 24 小时有效期，预览与确认同上；弹窗写明「谁能在这个终端会话里运行命令，谁就拿到这些权限」。已有生效授权的会话显示「已授权」（按服务端给的 `effective`，会话结束后复活的授权不再显示），抽屉里可撤销；「设置 → 权限 → 会话授权」每行带「生效中 / 未生效」标签与剩余时间，生效中的行可「续期」（选 1 / 4 / 24 小时，把**同一条**授权的到期时间从「现在」往后挪，权限范围不变；未撤销 / 未过期 / 会话未结束的才能续期，其余要重新授权）；会话抽屉的「已授权」条在最早一条剩余不足 1 小时时直接给出剩余时间与「续期」，用的是同一个弹窗。plan 详情页的链控制区有「结束通知」开关（等同 `plan set --notify on|off`）。

## 统计页

`/dashboard` 回答「一段时间里干得怎么样」：范围切换 今日 / 近 7 天 / 近 30 天 / 全部，「复制统计」；任务、耗时、Git 活动、信号（轮次 / 工具调用 / 人介入）、产出趋势、活跃热力图、项目 Top 3、验收与计划、耗时最长 / 最快、用量（费用与 token，job 与终端会话合并）；底部「系统」折叠区是实时状态卡。没有数据来源的指标显示「—」。只统计 gofer 自己的消耗，没有供应商额度。老 job 缺指标时管理员可跑 `gofer tool stats-backfill`。

## 受限调用方（上限）看到的界面

管理员可以在服务器配置里给某个 token 写「上限」（`server.callers[].ceiling`）：限定它只能碰哪些项目、能用哪些 runner / worker / agent、能不能跑 exec 任务，或者干脆只读。控制台读 `whoami` 拿到本人上限，并照着它摆界面（服务端仍然自己判定，界面只是不摆出注定被拒的选项）：

- **下拉只列范围内的项**：新建 job、新建会话、workflow 模板向导里的项目 / runner / agent 都按上限过滤。范围外的不显示；runner 这类本来就会因别的理由灰显的地方（项目不可达、worker 离线等）改成灰显并写明「超出你的调用方上限」。项目被藏起来时页面上有一句「N 个 project 超出你的调用方上限，未列出」。
- **exec 任务**：上限没写 `allow_exec` 的调用方，exec 类 agent 不出现在下拉里（提交也会被拒）。
- **只读 token**（上限里 `read_only: true`）：所有写入口消失——顶栏「新建任务」、会话页的「新建会话」、计划 / 工作流 / 定时的创建入口与表单，以及按权限显隐的那些操作（改配置、升级 worker、管理授权……）；顶栏挂一个「只读」徽标（悬停有说明），新建 job 页的提交按钮不可用并写明原因。job 详情页同样只剩查看：重建、取消、删除记录、合并到基线 / 交付、继续会话 / 续接、会话发消息、交互作答、评论输入、验收与批准都不摆（按钮位置留一行灰字说明），日志、事件、验收材料、评论列表照常可看。
- **验收 / 批准按权限显示**：要有 `job.review`；验收（或驳回、批准）**别人**提交的 job 还要 `job.review.others`。受限调用方（带 `ceiling` 的 token）不能审阅「上限所有者是自己」的 job（即自己提交的那条），需要别人来验收。不满足时按钮收起，原位置给一行灰字写明原因（只读身份 / 没有审阅他人 job 的权限 / 受限身份不能审阅自己的 job）；验收台 `/review` 的行内「通过 / 拒绝」同一条规则。服务端仍是权威，界面只是不摆注定被拒的按钮。
- **全局用量类字段整块省略**：受限调用方调 `/v1/stats` 拿不到 `db` / `sessions` / `usage` / `session_usage`，调 `/v1/today` 拿不到 `usage_today` / `steward_today`；控制台在这些字段缺省时**整块不显示**（统计页的系统卡、今天页状态条的用量与管家项），不显示 0。
- **「设置 → 权限」页顶部**给出本人上限摘要（项目 / runner / worker / agent / exec / 全局记忆 / 只读）；它也是「我为什么做不了某件事」的落地点。上限由管理员在配置文件里改，控制台不能自己放宽。
- 上限与权限是两层：上限是「最多能到哪」，权限是「允许做什么」，两者同时成立才放行。范围外的资源一律按不存在处理（404），只读 token 的写操作是 403。
- 没有上限的 token（以及 worker / job 凭据）看到的界面与以前一样。

## 实时刷新与手机

- 页面实时刷新；连接断开超过 15 秒自动改为低频轮询，恢复后自动切回。顶栏状态点显示「已连接 / 重连中 / 已断开·兜底轮询」，server 升级后提示「有新版本」。
- 顶栏还有两个提醒：有未决申请时，持有 `worker.manage` 的人会看到「worker 申请 N」（点它跳到 Runners 页的待接受区）；「待我决策 N」见上。信箱信封按钮上的待指派徽标见「导航」。
- 手机用 HTTPS 打开可「安装应用」成独立窗口 PWA 并收 Web Push，步骤见 [operations.md](operations.md)「HTTPS 入口」。
- 手机上新待办的提示条压成单行、几秒后自动收起（宽屏仍是底部常驻，等你自己关）：窄屏提示条会盖住正在看的会话，消息区要留给消息。工作台列表里「已结束」分组默认折叠，并且折叠时这些行根本不渲染，展开才加载。
- 经反向代理访问时，代理需放行 WebSocket（Upgrade 头）、关缓冲、空闲超时大于 60 秒。
